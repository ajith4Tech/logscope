# Logscope — deployment architecture

What runs where, how logs flow, and what must be in place before installing
the `logscope` Helm chart. Step-by-step commands are in [README.md](README.md).
Every setting is in [values.yaml](values.yaml).

**⚙** marks anything that depends on deployment configuration.

## Architecture

```
 INSIDE k3s                                              │  OUTSIDE k3s
                                                         │
 every node:                                             │
 ┌────────────┐ JSON stdout ┌───────────────────────┐    │
 │ Falco      │────────────►│ /var/log/pods         │    │
 │ DaemonSet  │             │ (all container logs)  │    │
 └────────────┘             └───────────┬───────────┘    │
                                        │ tail           │
                            ┌───────────▼───────────┐    │    ┌───────────────────┐
                            │ Vector DaemonSet      │    │    │ AWS S3 bucket ⚙   │
                            │ merge, classify, gzip │────┼───►│ <keyPrefix>/...   │
                            │ disk buffer on node   │    │    └─────────┬─────────┘
                            └───────────────────────┘    │              │
                                                         │              │ List/Get
 namespace ⚙ (e.g. logging):                             │              │ every 30s
 ┌───────────────────────────────────────────────┐       │              │
 │ Logscope web app (Deployment, 1 pod)          │◄──────┼──────────────┘
 │ SQLite cache + anomaly state on PVC           │       │

 └───────────▲───────────────────────────────────┘ HTTPS │     Anthropic | Gemini |
             │ :8000                                     │     OpenAI | OpenRouter
 ┌───────────┴──────────────┐                            │
 │ Service (ClusterIP)      │◄── kubectl port-forward    │
 └───────────▲──────────────┘                            │
             │ NetworkPolicy: only Traefik may connect   │
 ┌───────────┴──────────────┐                            │

 └──────────────────────────┘                            │     firewall ⚙
                                                         │
                                                         │  Container registry ⚙ (optional):
                                                         │  nodes pull the web app image
```

## 1. Inside k3s

| Component | Kind | Deployed by this chart? | Notes |
|---|---|---|---|
| **Logscope web app / API** | Deployment (1 replica, `Recreate`) | **Always** | UI and API on port 8000. Polls S3, caches in SQLite, detects anomalies, calls the AI provider. Non-root, read-only root FS, no Kubernetes API token. Cluster actions (kubectl) are disabled |
| Service | ClusterIP, port 8000 | Always | `<release>-webapp` |
| PersistentVolumeClaim | 2Gi ⚙, default StorageClass ⚙ | Always (⚙ `persistence`) | SQLite log cache and anomaly triage state. Kept on `helm uninstall` |
| ConfigMap | web app `config.yaml` | Always | S3 location, classification, AI provider/model defaults (the Settings tab can override them at runtime). **No credentials** |
| Secret(s) | Opaque | Only for credentials given inline in values ⚙ | Otherwise the chart references existing Secrets |
| NetworkPolicy | ingress-only | Default on ⚙ | Only Traefik (kube-system) may reach port 8000. Egress is not restricted by the chart; with a default-deny egress policy, allow S3, the AI provider, DNS and every alert channel host (README → "NetworkPolicy and egress") |
| Ingress + Traefik Middlewares | — | Only if `ingress.enabled` ⚙ (default off) | HTTPS-only, basic auth, HTTP→HTTPS redirect |
| **Vector** | DaemonSet + RBAC (read pods/namespaces/nodes) + ConfigMap | **Optional** (`vector.enabled`, default **off**) | Today Vector runs as a separate Helm release `vector` (namespace `logging`, generated by `scripts/render.py`). The chart refuses to install its own Vector while that release exists |
| **Falco** | DaemonSet (official `falcosecurity/falco` 9.1.0, bundled) | **Optional** (`falco.enabled`, default **off**) | Today Falco runs as a separate Helm release `falco` (namespace `falco`) with JSON-to-stdout enabled. The chart refuses to install its own Falco while that release exists |

Default install against the current cluster: **web app only**. The existing
Vector and Falco keep running unchanged.

## 2. Outside k3s

| Service | Used by | Required? |
|---|---|---|
| **AWS S3 bucket** ⚙ (bucket, region) | Vector writes, the web app reads | Required |
| **AI provider** ⚙: Anthropic, Google Gemini, OpenAI or OpenRouter (optional custom endpoint) | Web app only | Optional (`ai.provider: none` disables it) |
| **DNS provider, public IP / load balancer, firewall** ⚙ | Users reaching the UI by hostname | Only when the Ingress is enabled. The cluster currently has no public address (Traefik is on the node's internal IP) |
| **Container registry** ⚙ | Pulling the web app image | Only for multi-node clusters or if you choose one. None is configured today; single-node installs import the image directly into k3s. Vector and Falco images come from public Docker Hub/registries |
| Certificate authority / cert-manager ⚙ | TLS for the hostname | With the Ingress. cert-manager isn't installed today |

## 3. Data flow

**Logs (always on):**

1. Containers write to stdout. k3s stores this as files under `/var/log/pods` on each node.
2. **Vector** tails the files and works through these steps:
   - joins multi-line events (stack traces);
   - classifies each line into a severity bucket (`error`, `warning`, `info`, `debug`, `metrics`) and a scope (infra namespaces ⚙ or `namespaces/<ns>`);
   - formats one line per event: `<time> - <namespace> - <pod>/<container> - <message>`.
3. **Falco events** are ordinary pod logs from the Falco namespace ⚙. Vector recognises them by that namespace and Falco's container name (`logscope.falco.containers`, default `falco`) and maps Falco priority to severity ⚙. It writes them once, under a separate `security/<severity>/` prefix; the main severity prefixes leave them out.
4. Vector batches events (up to 50 MB or 10 minutes), gzips them, and uploads
   objects under `<keyPrefix>/<severity>/YYYY/MM/DD/…` ⚙. The default
   `keyPrefix` is `k3s-logs/logs/{{ log_type }}/%Y/%m/%d/%H_%M_%S_`. If S3 is
   unreachable, events wait in a disk buffer on the node: 2.5 GiB per S3
   sink, so up to 5 GiB when Falco routing is on (its `security/` prefix is a
   second sink).
5. The **web app**:
   - lists new objects every 30 s ⚙, re-checking the last hour so late uploads aren't missed;
   - downloads, decompresses and parses them into its SQLite cache on the PVC;
   - prunes records older than `s3.retentionDays` ⚙ (30). The bucket's own
     lifecycle rule deletes old objects in S3.
6. Users query the cache through the UI/API. **Logs never flow from the web app back into the cluster.**

**AI (optional):**

- Every 5 minutes the web app runs anomaly detection on the cache (error spikes,
  new Falco rules, message-frequency spikes, severity shifts).
- For up to 5 new anomalies per run ⚙, it sends the anomaly evidence and a few
  sample messages to the AI provider.
- An operator can also click "explain". That sends either up to 50 filtered log
  lines or one log line.
- Responses (summary plus suggested read-only diagnostic steps) are cached and
  shown in the UI. Suggested commands are **not executed** by Logscope.
- **Consequence: AI calls send log content outside the cluster.** Before
  sending, the app removes common credential and personal-data patterns
  (passwords and other `key=value` secrets, bearer/basic credentials, JWTs, AWS
  key IDs, well-known API tokens, URL passwords, private keys, email
  addresses) and caps each value at 2,000 characters and each request at about
  48,000. This is pattern-based and not complete: anything else applications
  log (names, customer IDs, IP addresses, unusual secret formats) is sent, and
  the provider's retention terms apply. AI is off unless
  `ai.provider` is set ⚙.
- Operator-triggered AI calls are rate-limited (`ai.rateLimitPerMinute` ⚙,
  default 10/min, in memory per pod).

## 4. Deployment dependencies

| Dependency | What's needed | Where it's configured |
|---|---|---|
| **S3 bucket** | Bucket and region. Retention lifecycle rule applied once (`scripts/apply_s3_lifecycle.py`) | `s3.bucket`, `s3.region`, `s3.keyPrefix` ⚙. With the existing Vector, these must match the `config.yaml` it was rendered from |
| **S3 credentials: web app** | Read-only IAM key: `s3:ListBucket` (prefix-scoped) + `s3:GetObject` on `<bucket>/<prefix root>/*` | `s3.credentials.webapp` (existing Secret or inline) ⚙ |
| **S3 credentials: Vector** | Write IAM key: `s3:PutObject`, `s3:AbortMultipartUpload`. An existing Vector install reads it from the Secret named by `sinks.s3.secret_name` in its `config.yaml` (default `vector-s3-creds`) | `s3.credentials.vector`, only if the chart manages Vector ⚙ |
| **AI API key** | Key for the chosen provider, plus an explicit model ID | `ai.provider`, `ai.model`, `ai.apiKey` or `ai.existingSecret`, optional `ai.baseUrl` ⚙ |
| **Image distribution** | Distroless web app image built from the repository `Dockerfile` (`make image`; `logscope` binary, no shell) with an immutable tag | `image.repository`, `image.tag` (default: chart `appVersion`), optional `image.digest` ⚙. Single node: import into k3s (`make k3s-import`, `image.pullPolicy: Never`). Multi-node: push to a registry all nodes can pull from (`make image-multi PUSH=1`, + `image.pullSecrets`) |
| **Outbound network** | DNS and HTTPS 443 from the nodes to S3 and the AI provider | Cluster or network firewall ⚙ |
| **Storage** | A StorageClass for the PVC (`local-path` is the cluster default today) | `persistence.*` ⚙ |
| **DNS** (optional) | A/AAAA/CNAME for the UI hostname → an address reaching Traefik on 80/443 | DNS provider; `ingress.host` ⚙ |
| **TLS** (with Ingress) | Certificate for the hostname as a `kubernetes.io/tls` Secret, or cert-manager | `ingress.tls.secretName` ⚙. Without it, Traefik serves a self-signed certificate |
| **Authentication** (with Ingress) | htpasswd Secret for Traefik basic auth, or SSO in front | `ingress.basicAuth.secretName` or `ingress.externalAuth` ⚙. **The app has no login of its own** |

## Things to know

- **The default is internal only.** The UI is reached with
  `kubectl port-forward`. Exposing it without authentication and TLS is
  blocked by the chart.
- **One web app pod.** Upgrades cause a few seconds of downtime, and there is
  no high availability. Everything in its cache except anomaly triage state can
  be rebuilt from S3.
- **Credentials in values.yaml** become Kubernetes Secrets but also live in
  Helm's release record. Prefer existing Secrets, and never commit a filled-in
  values file.
- **AI settings from the UI** (Settings tab) are protected by an admin token
  and stored in the state database; a key entered there is encrypted with a
  master key (`/state/secret.key` or `settings.secretKey.existingSecret`).
  Losing or replacing the master key makes a stored key unreadable (the app
  warns and keeps running). Rotation: README → "Rotating the master key".
- **Chart-managed Vector or Falco** replaces the existing releases; it doesn't
  run alongside them. See README → "Existing vs Helm-managed Falco/Vector".
